Sources. Tanium 15-day server report (about Sept 1–16, 2026); Palo Alto egress firewall logs for traffic to Zscaler (37 extracts, May 22 – Sept 1, 2026) and to CrowdStrike (egress firewalls only), used as source-to-destination evidence for every device; IPAM all_IP_networks v20261002r9 for device type.

Device types. Remote-access users are RA pools and VPN; site users and devices are campus, wireless, call-center, distribution, specialty and similar space, plus subnets IPAM labels as network management or data center where the addresses are user endpoints (see notes below); VDI user sessions are user-VDI subnets without a Tanium agent.

"Palo Alto, no Zscaler internet" for non-Tanium devices means the firewall logs show no Zscaler internet (ZIA) traffic from them. Zscaler Private Access is not internet egress (it carries users to internal apps through an App Connector) and is not counted as a separate path; the 2,341 devices whose only Zscaler traffic was ZPA are in this group. Whether their web traffic also uses a proxy is not visible in this data.

Cloud. Only the Azure hub firewalls appear in these logs. AWS and GCP servers reach the internet through the provider's own gateways, which are not in the Palo Alto logs, so they are not in the site view.

Server coverage. Servers are counted only when they appear in the Palo Alto log extracts, which for servers means almost only the CrowdStrike extract. That extract has few rows from the Azure hub firewalls, so Azure is undercounted: 308 servers here against 7,021 Azure servers with internet traffic in Tanium. Across all sites the page shows 15,767 of about 26,000 Tanium application and Citrix servers with internet traffic. A Tanium-based server count by routing domain would close this gap.

Device counts, not traffic volume. The firewall extracts are source-to-destination pairs without session counts, so this page counts devices. The share of traffic volume needs a Splunk extract with session counts per source over one window.

ZPA App Connectors are excluded. The 158 Zscaler App Connector servers (Tanium APM0013984 zsc) do not browse the internet: their traffic to Zscaler is the ZPA broker tunnel plus ping/traceroute probes to Zscaler data centers. 373 application servers in IPAM subnets labelled RA-CONN-ZPA are ordinary application servers and are counted as such. Zscaler internet here means the firewall identified the app as Zscaler internet access, or web traffic to a Zscaler proxy address; ping/traceroute-only rows are not counted.

User devices in server address space. 2,602 addresses in subnets IPAM labels as data center or application space (DataCenter, APP-DATA, cloud) send Zscaler Client Connector traffic (ZIA and ZPA). Servers do not run Client Connector, and Forescout identifies the ones it knows as workstations, laptops and desktops, so they are counted as site users and devices. The largest are 10.115.192.0/20 at Shea (383), 10.178.32.0/19 at Middletown (324) and 10.134.220.0/24 at RI One (173). "Servers with no Tanium agent" is the 2,975 server-space addresses that leave through the Palo Alto with no Zscaler traffic, including 123 addresses in INFRA and RA-CONN-ZPA subnets that an earlier version miscounted as remote-access users.

Distribution-center operational devices are addresses in subnets IPAM labels Management, mostly at distribution centers: iBase industrial PCs (699), mobile handhelds and tablets (about 190), Zebra scanners and printers (32), plus 28 network appliances (FTD, switches, Infoblox). They do not use Zscaler; 70 addresses in that space that do are counted as site users. Left out: 3,969 public internet addresses (inbound sources arriving at the RI external firewalls, not CVS devices) and 28 internal addresses with no usable IPAM classification (15 with no IPAM subnet, plus Nashville call-center, partner-site and SNAT addresses).

Management space. 2,045 addresses in 62 subnets that IPAM labels as access-point or switch management (MGT-AP 41, MGT-L2SW 19, WAN 2) are user clients, confirmed by Client Connector traffic and Forescout. All management-space addresses are counted as site users and devices. Every one of those subnets also holds active APs or switches, so most are shared management and user VLANs (worklist: ipam_nettype_user_reclass_candidates_v20261002.csv).
